**The seventh item, the speaker device list - NOT BUILT (it cannot be done in Unity 6000.0 without more than a script).** The microphone list works because `Microphone.devices` exists. Unity has no counterpart for the OUTPUT: `AudioSettings` has no way to list or pick an output device, the game's sound goes to whatever Windows says the default is, and a change of the default is only reported (`AudioSettings.OnAudioConfigurationChanged`) - see the Unity forum threads "Change audio devices in runtime" (discussions.unity.com/t/change-audio-devices-in-runtime/929500) and "How can I change the sound output device" (discussions.unity.com/t/how-can-i-change-the-sound-output-device/916271), and the issue tracker's "changing default audio output device does not change audio output device in editor and build". That is why the SPEAKERS row has a button to Windows' own "App volume and device preferences" page (2.64). The ways to get a real list: (a) **FMOD for Unity** (audio middleware; `System.setDriver` lists and switches output devices; it replaces Unity's audio for the whole game, which is a large change; check its current licence terms before choosing it), (b) a **native plugin** that opens the chosen device itself and plays Unity's mix into it (`OnAudioFilterRead` into miniaudio or similar: new latency and a plugin to ship for the IL2CPP build), (c) the undocumented Windows call that sets one application's default endpoint (fragile across Windows versions). Not started; the owner decides (a) / (b), or keeps the button.
